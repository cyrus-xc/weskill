# weSkill 0.5.0

为减少密集调用、避免被探测，本次加入以下原生调用限制与采集控制。

- **共享请求额度**：同一本机用户的所有进程共用滚动窗口，任意连续60秒最多20次原生业务请求；读取、发送、历史分页和连接启动尝试统一计入。达到额度后等待，重启不清零。
- **随机串行锁**：所有原生操作共用跨进程锁，覆盖执行与错误处理；结束后继续持锁随机1–3秒才释放。下一次原生操作必须等待，历史每页分别加锁。
- **降低重复采集**：会话检查间隔15秒，好友申请检查间隔60秒；查询容量与快照持久复用，共享事件目录的MCP实例复用同一检查时间表。
- **按新增范围读取历史**：初始化仅建立基线，不拉取全部聊天历史；变化会话从20条开始按需扩展，已有事件库升级不触发全会话重扫。手动历史查询仍支持自定义条数及全部记录。
- **减少申请列表附加查询**：后台采集跳过逐条联系人关系补查，保持未知状态的原义；手动好友申请列表保留完整默认行为。
- **异常后暂停**：原生采集失败即持久暂停，服务重启不会自动解除；处理客户端问题后，显式使用 `resume=True` 恢复，遵循返回的 `status`、`pause_reason` 与 `next_poll_seconds`。
- **执行器状态检查退避**：等待期间从50毫秒逐步延长至1秒，减少超时过程中的持续状态查询。
- **发送与缓存语义保持**：发送仍以客户端成功返回为准；本机服务状态和缓存事件读取不占原生请求额度；原生请求才进入串行锁。

## 安装

```bash
npm install -g weskill@0.5.0
weskill setup
```

已有MCP进程需重连后加载新代码。原生业务仍适配已验证的Linux ARM64微信构建，具体范围见兼容性报告。

## 验证

通过140项离线Python测试，并验证跨进程互斥、随机冷却、滑动窗口、分页排队、异常暂停和重启恢复。本轮未对真实微信客户端执行请求，检测效果尚未验证。
