# weskill × we-Agent 联合开发约定

两个仓库分别维护、分别发布，围绕一个完整控制流协作：微信事件进入 Agent 流程，Agent 结合任务与知识生成动作，通过 weskill 执行，再记录客户端结果。

- [weskill](https://github.com/cyrus-xc/weskill)：开源 Skill 与微信执行底座。
- [we-Agent](https://github.com/cyrus-xc/we-Agent)：Agent 流程管理与常驻响应控制层。

本文是跨仓职责和现有操作契约的主要文档。we-Agent 的架构文档引用本文；原生入口、地址和对象布局不成为两个仓库的公共接口。

## 职责归属

| 领域 | weskill | we-Agent |
| --- | --- | --- |
| 微信原生调用 | ABI、线程、对象、回调与构建适配 | 调用公开接口 |
| 操作能力 | 消息、媒体、好友、群、表情、朋友圈 | 将操作编排成流程动作 |
| Skill | 能力目录、领域操作流程与参数指导 | 选择并使用能力 |
| 事件采集 | 识别微信新消息/好友申请、归一化事件 | 订阅/消费、路由和触发流程 |
| Agent 执行 | 提供工具结果 | 模型调用、会话状态、任务调度 |
| 知识与边界 | 如实返回数据和客户端权限错误 | 知识库、流程规则、行为边界、人工接管 |
| 常驻与界面 | 执行服务及原生 worker 的生命周期 | 独立驻守进程、流程管理看板 |
| 结果记录 | 原生结果与操作幂等账本 | 流程运行记录、动作状态与业务日志 |

不在 weskill 增加联系人白名单、业务配额或流程知识库。we-Agent 中由部署者配置的业务规则，也不转成 weskill 固定的能力限制。

## 当前可依赖的操作接口

weskill 已提供 stdio MCP 和五个 Skill。MCP 会话通过 `get_capabilities` 与工具发现确定实际能力，再调用 `ensure_service`。执行服务仅在本机以同用户 Unix socket 工作；外部消费者使用 MCP，不直接依赖其私有 socket 协议、worker 管道或内部 Python 方法。

使用方保存以下信息：

- 具体目标的内部 ID；姓名只用于搜索与消歧。
- 每个动作的独立幂等键、精确输入和客户端结果。
- 读取结果的分页游标、范围和不完整标识。
- 原始错误类型与阶段，不能一律转为“可重试”。

成功标准为 `client_success`，无需自动回查历史。`unknown` 保持不确定，不自动发起第二次提交；`not_submitted` 才允许显式原键再试。幂等键不能因为工具超时、流程恢复或 Agent 重新推理而变化。

例如一个流程实例可以保存动作键 `run-example/action-02`。这是格式示例，执行层不要求前缀或长度配额；关键是同一动作恢复时复用原值。不同动作不能共用一个键。

## 常驻进程与执行服务

we-Agent 驻守进程负责持续运行、Agent 任务和业务流程；weskill 执行服务负责共享连接、原生串行化和在途资源。

当前执行服务从最后一次请求完成起空闲一小时退出，再次操作自动启动。这个超时不决定 we-Agent 进程是否退出。不要通过强杀 native worker 来暂停流程：可能仍有原生回调在使用它的资源。流程暂停首先阻止新动作，在途动作按实际结果收尾。

## 事件接口的开发边界

**当前发布的 weskill 没有实时事件订阅工具；we-Agent 当前仓库提供架构与协作文档。** README 中的常驻响应是双仓职责描述，不是已运行的实时闭环。事件实现和传输方式在专项设计时确定，下面记录协作所需的语义，不预先注册不存在的 MCP 工具。

事件接口需要保留：

- 稳定事件身份与会话/申请身份，便于消费方去重。
- 事件来源、发生时间、读取时间和事件类型。
- 恢复位置与缺口信息，区分实时收到、补读和历史回放。
- 自己发出的消息与外部消息的区分，避免响应自己的输出。
- 好友申请的来源记录与处理状态，不因重复通知重复接受。

可靠性目标是可恢复、可去重的消费，不承诺模型或微信网络具备“恰好一次”。事件去重由消费者维护，微信写操作去重由 weskill 账本维护，两者关联但不混成一份状态。

收到外部消息只构成流程输入，不自行赋予对方修改规则、群设置或知识库的权限；动作是否执行由 we-Agent 的流程和操作者配置决定。

## 两仓一起开发的方法

推荐在同一级目录保存两个独立 checkout。仓库之间不建立源码软链接，不跨仓导入业务模块，也不把本机绝对路径写进公共配置。we-Agent 使用独立安装的 weskill MCP 进程。

跨仓功能按以下顺序形成可审阅产物：

1. 在本约定或关联设计文档写清输入、输出、失败与所有权归属，区分已提供接口和草案。
2. 在 weskill 实现原生能力、工具契约与测试；使用能力发现提供新增操作。
3. 在 we-Agent 实现调用与流程状态，覆盖超时、重启和重复输入。
4. 两仓变更互相引用提交或 PR；记录实际验证过的版本组合。
5. weskill 可独立安装测试通过后再发布，we-Agent 不依赖另一个仓库尚未发布的内部文件。

兼容的字段增加保留旧含义；改变参数或状态语义时记录迁移方式并更新消费者。版本号只用于定位，运行时仍以能力与 schema 为准。跨仓测试只能声称实际使用过的版本组合，不以“使用最新版”替代结果记录。

## 验证分工

weskill 负责协议、幂等、分页、精度、原生所有权和适配构建验证；we-Agent 负责事件路由、流程状态、Agent 动作、知识库边界和恢复。联合验证覆盖“一个输入触发一个业务动作，超时或重启后不重复发送”。

自动测试使用隔离替身；真实微信集成使用明确授权的测试联系人和群。原始消息、申请凭据和研究报告保留在本地忽略目录，跨仓只交换脱敏结果。
