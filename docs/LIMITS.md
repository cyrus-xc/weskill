# 当前约束清单

目标是先把微信操作跑顺。以下区分已移除的人为限额、尚存的实现条件与功能缺口。

## 已移除

- 联系人与群白名单，以及联系人配置文件。
- 历史最多20条：默认20，正整数自定义，0或null拉全部本机可读记录，内部按时间分页。
- 搜索最多50条、关键词最多8项/每项128字符、批量会话最多8个。
- 正文4096个UTF-16单位、幂等键128字符、原生返回字符串64KiB、本机请求帧1MiB。
- 只允许wxid或数字群ID的格式假设：filehelper和旧式用户名也可直接传入。
- 强制关闭XML、强制固定搜索排序：改为调用方选项。
- 明确未提交也禁止原键再试：not_submitted允许原键再次调用。
- 子进程第二份发送幂等记录：由外层保留一份持久发送记录。
- 本机服务170秒的聚合响应截止时间：全量分页不设此截止时间。

发送以客户端返回client_success作为成功，不做历史回查。

## 仍保留的实现条件

| 项目 | 当前行为与原因 |
| --- | --- |
| 原生构建 | 只适配Linux ARM64微信4.1.13.26的已研究文件哈希、路径/opt/wechat/wechat和Frida16.7.19。地址、指针布局和入口指令是当前实现的依据，不能移除检查就声称兼容其他版本。 |
| 原生线程与生命周期 | 核对PID、映射和executor线程；请求串行执行；回调脚本保留到微信退出。这是当前桥接实现，长期调用会积累脚本与内存，后续需优化。 |
| 历史读取 | 原生JSON接口每次最多200条；工具箱以时间游标分页绕过总量限制，同秒密集记录使用较大有限页，避免边界漏读。每会话只返回客户端本机可读的数据。 |
| 连接超时 | 附加15秒；全新worker启动等待22秒，连接阶段最多两次。业务已接收后不自动重放。 |
| 单次原生操作 | 每次RPC、executor等待或回调等待30秒；父进程等待单次worker结果100秒。全量请求分成多次原生页；这些仍是当前实现设置，不是微信的业务配额。 |
| 控制操作超时 | 服务启动10秒；状态/停止响应3秒；停止后等socket移除7秒；请求输入等待10秒。宿主自己的MCP工具超时另行配置。 |
| 去重 | 同键同目标正文防重复提交；媒体还绑定操作类型、本机路径和文件 SHA256；同键换目标或正文会报错；unknown不自动重发。新发送任务使用新键。 |
| 基础参数 | 类型正确、需要的字符串非空、无NUL、Unicode有效。没有人为长度或数量配额，客户端自身拒绝则返回原错误。 |
| 本机服务 | 同用户Unix socket，单帐号；服务空闲一小时退出，在途请求不被强制中断。一小时来自用户要求。 |
| 客户端重启 | 微信PID或原生库、记录目录改变后，结束当前业务并停止旧服务再连接。切换联系人或群不需要重启。 |

没有额外的发送频率、每日条数、发送间隔或收费限额。

## 功能缺口

当前业务为联系人/群搜索、历史查询、私聊/群聊文本发送，以及私聊验证的本地图片和文件发送、原生群管理。媒体无工具箱大小与扩展名上限；会在活跃帐号缓存保留副本，特殊字符或重名可能调整实际文件名。群媒体与其他格式尚未逐项验证。自定义表情、实时事件、完整好友资料与备注、好友申请、朋友圈和截图尚未实现，并非通过开关禁用。

不自动切换UI操作；先说明原生失败原因、再与用户确认UI方案，这条流程来自用户最初要求。

## 群管理的实现范围

普通 `@chatroom` 群已适配，其他群类型未验证；移出成员前刷新本人角色，仅群主或管理员可提交；权限仍由微信处理。成员查询当前返回ID与角色，完整昵称资料尚未返回。公告为完整纯文本替换，不保留富文本附件；消息置顶需要非零、可解析为原生 uint64 的服务器消息 ID。查询结果说明缓存或刷新来源，邀请确认值由客户端联系人缓存提供。邀请模式实测成功，直接添加可能被微信拒绝，工具箱不自动换模式重发。以上是实现范围，没有新增频率、人数或消息长度配额。
