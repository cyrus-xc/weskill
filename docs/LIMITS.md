# 当前约束清单

目标是先把微信操作跑顺。以下区分已移除的人为限额、尚存的实现条件与功能缺口。

## 已移除

- 联系人与群白名单，以及联系人配置文件。
- 历史最多20条：默认20，正整数自定义，0或null拉全部本机可读记录，内部按时间分页。
- 搜索最多50条、关键词最多8项/每项128字符、批量会话最多8个。
- 正文4096个UTF-16单位、幂等键128字符、原生返回字符串64KiB、本机请求帧1MiB。
- 只允许wxid或数字群ID的格式假设：filehelper和旧式用户名也可直接传入。
- 强制关闭XML、强制固定搜索排序：改为调用方选项。
- 明确未提交也禁止原键再试：not_submitted允许原键再次调用。
- 子进程第二份发送幂等记录：由外层保留一份持久发送记录。
- 本机服务170秒的聚合响应截止时间：全量分页不设此截止时间。

发送以客户端返回client_success作为成功，不做历史回查。

## 原生请求频率

所有原生业务操作及连接启动尝试共用一把跨进程锁。锁覆盖整次执行、错误处理和结束后随机1–3秒冷却，冷却完成才释放；下一次原生操作必须等待。历史每页分别经过此锁。冷却截止时间持久保存，进程退出或重启不会直接清除尚未到期的冷却。原生子进程复用父进程已经持有的锁，不重复上锁。

所有原生业务操作在提交前共享每用户、跨进程、跨重启的滚动额度：任意连续60秒最多20次。原生连接启动尝试和历史分页每页分别计入，读取和发送共用额度；超出时等待可用额度，不截断返回条数。`get_service_status` 的本机状态读取不占额度，并返回当前用量。此额度不代表微信服务端认可的安全阈值。

## 仍保留的实现条件

| 项目 | 当前行为与原因 |
| --- | --- |
| 原生构建 | 只适配Linux ARM64微信4.1.13.26的已研究文件哈希、路径/opt/wechat/wechat和Frida16.7.19。地址、指针布局和入口指令是当前实现的依据，不能移除检查就声称兼容其他版本。 |
| 原生线程与生命周期 | 核对PID、映射和executor线程；请求串行执行，共用一个执行桥。业务脚本仅在原生任务空闲且回调对象完成销毁后释放；未完成或状态不明时保留，下次请求再检查。worker退出时仍可能被原生引用的脚本留存到微信退出。旧版本已留存脚本无法追溯释放。 |
| 历史读取 | 原生JSON接口每次最多200条；工具箱以时间游标分页绕过总量限制，同秒密集记录使用较大有限页，避免边界漏读。每会话只返回客户端本机可读的数据。 |
| 连接超时 | 附加15秒；全新worker启动等待22秒，连接阶段最多两次。业务已接收后不自动重放。 |
| 单次原生操作 | 每次RPC、executor等待或回调等待30秒；父进程等待单次worker结果100秒。全量请求分成多次原生页；这些仍是当前实现设置，不是微信的业务配额。 |
| 表情素材等待 | 原生下载排队后最多等待30秒取得素材；超时明确返回未发送。下载和解密沿用客户端，不添加收藏。 |
| 控制操作超时 | 服务启动10秒；状态/停止响应3秒；停止后等socket移除7秒；请求输入等待10秒。宿主自己的MCP工具超时另行配置。 |
| 去重 | 同键同目标正文防重复提交；媒体还绑定操作类型、本机路径和文件 SHA256；同键换目标或正文会报错；unknown不自动重发。新发送任务使用新键。 |
| 基础参数 | 类型正确、需要的字符串非空、无NUL、Unicode有效。没有人为长度或数量配额，客户端自身拒绝则返回原错误。 |
| 本机服务 | 同用户Unix socket，单帐号；服务空闲一小时退出，在途请求不被强制中断。一小时来自用户要求。 |
| 客户端重启 | 微信PID或原生库、记录目录改变后，结束当前业务并停止旧服务再连接。切换联系人或群不需要重启。 |

没有额外的发送频率、每日条数、发送间隔或收费限额。

## 功能缺口

当前业务为联系人/群搜索、历史查询、私聊/群聊文本发送，以及私聊与普通群验证的本地图片和文件发送、原生群管理。媒体无工具箱大小与扩展名上限；会在活跃帐号缓存保留副本，特殊字符或重名可能调整实际文件名。普通群 PNG 与文本文件已验证，其他格式尚未逐项验证。好友本地资料、备注修改和申请记录查询已接入。主动添加和接受好友申请已由使用者实测通过。表情与朋友圈已接入，验证范围见各自文档；私聊增量事件通过 `get_events` 原生历史轮询读取，不是推送 Hook；在轮询前已被删除或撤回且不留本地记录的消息可能无法观察。

界面辅助已按用户要求移出项目范围；原生失败时报告实际原因。

## 群管理的实现范围

普通 `@chatroom` 群已适配，其他群类型未验证；移出成员前刷新本人角色，仅群主或管理员可提交；权限仍由微信处理。成员查询返回ID、角色、群昵称和可用本地联系人资料，缺失记录与资料查询状态单独标明。公告范围确定为完整纯文本替换，富文本附件不在开发计划中；消息置顶需要非零、可解析为原生 uint64 的服务器消息 ID。查询结果说明缓存或刷新来源，邀请确认值由客户端联系人缓存提供。邀请模式实测成功，当前以已验证的邀请路径满足拉人入群需求，直接添加不再列为待办；工具箱不自动换模式重发。以上群管理能力不另设人数或消息长度配额，统一使用上述原生请求额度。

朋友圈只暴露已恢复的公开与仅自己可见两种隐私参数；不猜测部分可见名单语义。图片上传路径必须通过微信自己的 CDN 路径校验；图片放入活跃帐号缓存。`0` / `null` 表示可访问分页，不突破微信权限或数据留存范围。
