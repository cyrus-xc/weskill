# 好友管理

`weskill-friends` 编排好友资料、备注和申请操作，与总入口和群管理共用本机 MCP、常驻服务和持久幂等记录。执行能力以当前 MCP 的工具列表和 `get_capabilities` 为准。

## 资料查询

`get_friend_info(contact_ids)` 批量读取微信本地联系人记录，可用于好友和已缓存的群成员。返回 `contacts`，每项包含 `contact_id`、`found` 及已取得的字段：微信号、昵称、备注、描述、签名、性别、国家/省/城市、头像地址、电话号码列表、标签和添加来源等。`source` 标注本地原生记录，`remote_refreshed=false`，不宣称刚完成远端同步。未找到的记录返回 `found=false`；电话号码是客户端资料中的可编辑列表，不代表隐藏的帐号绑定手机号；标签名来自本地缓存，未缓存的名称不填造；添加来源返回原始代码及已恢复的说明。企业/OpenIM 扩展资料尚未适配。当前测试联系人和测试群没有非空电话或标签样本，该分支尚未实测。

`get_group_members` 会合并这些资料并保留成员角色。群内昵称、联系人昵称和好友备注分别呈现，`display_name` 优先使用群昵称、其次备注和昵称。`profiles_status` 与 `profiles_errors` 说明批量资料查询的状态。

## 修改备注

`set_contact_remark(contact_id, remark, idempotency_key)` 设置指定好友的备注；空字符串清除。使用客户端联系人服务的更新与提交路径，客户端完成回执决定结果。原生更新可能先修改本地记录，再等待网络回执；未知结果保留原键，不因本地已变化而猜测请求成功。

修改与恢复是两个不同请求。常规修改成功后保留用户要求的新值；只有用户要求恢复或明确的测试清理才恢复旧值。

## 检查申请

`list_friend_requests(limit=20, offset=0)` 从客户端申请记录服务读取，按时间从新到旧返回。任意正整数设置条数，`0` 或 `null` 返回从 offset 起全部记录，不设工具箱条数上限。返回申请标识、请求内容、方向、原生状态及分页信息。记录可能包含历史项，未知状态不自动当作待接受。

## 添加与接受

`search_new_contact(query)` 使用微信原生网络搜索指定微信号等标识，不提交申请。

`add_friend(query, idempotency_key, greeting="", remark="")` 搜索用户指定标识后提交申请；`accept_friend_request(request_id, idempotency_key, remark=null)` 重新取得所选申请的验证凭据后接受，null保留其备注，空字符串清除。主动添加和接受必须使用客户端搜索或真实申请中的身份与验证凭据。查询成功、找到用户和申请提交是不同结果；发出申请也不表示对方已经接受。两项原生写入通道已接入，但真实添加和接受仍待专用测试对象验证；目前只验证了已有好友与不存在申请的未提交路径。

## 验证与边界

本地普通好友资料、申请列表和新联系人搜索已通过原生调用验证；临时备注修改及恢复均收到客户端成功回调，相同幂等键返回原结果。原始资料、票据和实验报告保存在被忽略的本地目录，不进入公开源码或发布包。

当前适配构建与平台条件见 [兼容范围](FEATURES.md#已验证构建)。未知或客户端拒绝不会自动转为 UI 操作。
