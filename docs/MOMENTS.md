# 朋友圈

本轮范围是读取时间线和个人动态、发布纯文字和本地图片。视频、点赞和评论不在本轮范围。

## 读取

`get_moments(limit=20, cursor=null, contact_id=null, include_xml=false)` 默认读取时间线；指定联系人内部 ID 时读取个人动态。普通动态位于 `moments`，置顶动态独立位于 `top_moments`。每项含字符串动态 ID、作者、时间、正文、私密/置顶标记和客户端 XML 解码的 `details`；其中包含可用的媒体、位置等字段。`include_xml=true` 可保留完整原始 XML。

默认20条，可自定义数量；`0` / `null` 跟随当前可访问分页。继续查询使用原样返回的 `next_cursor`，并保持同一联系人范围。客户端首页缓存匹配不代表历史结束；服务按原生规则复用缓存并继续分页。`pagination_stalled=true`、`partial_result` 或客户端错误表示尚未确认读取完整，不把受限结果称为所有历史。

## 发布

`publish_moments(content, visibility, idempotency_key, image_paths=[])` 发布纯文字或一组本机图片。图片允许空正文，文字与图片不能同时为空。没有工具箱图片数量或文件大小配额；格式支持取决于图片解码库与微信客户端。

`visibility` 必填：`private` 是仅自己可见；`public` 按微信好友可见规则发布。本轮没有部分可见/排除名单接口。上传图和缩略图放入微信认可的本地缓存目录，由原生上传与发布流程处理。服务不会修改客户端的路径校验。

同键绑定正文、可见范围、文件路径与图片字节；超时保留同键，`unknown` 不重发。`client_success` 即按发布成功处理，动态 ID 保留字符串精度，不额外要求回查动态。

## 验证范围

时间线读取、游标续页和个人动态读取已在当前构建完成原生验证；本人动态全量查询通过两页读到可访问末尾。使用者明确授权后，纯文字与单张 PNG 输入的图文动态均以仅自己可见发布，取得客户端成功回调。公开发布使用同一原生通道，但本轮没有向好友发布测试内容；多图等组合尚未逐项实测。

原始动态、帐号 ID、发布返回值和实验报告仅保存在本地忽略目录。
